在 Agent 写第一行代码之前

deepcoding

从哪里读起

同样一句「做一个能工作的原型」，在空项目里和在多年积累的产品里，成本完全不同。前者容许边做边找方向；在后者，Agent 第一次选中的例子可能决定后面一整串实现。Lauren 用 deepcoding 指给上下文排顺序的做法：先提供左右实现的重要证据，再让模型动手。

再看一个细节

React 是她举的例子。假如仓库许多旧组件都滥用 useEffect，让模型搜遍相邻文件，它就很容易把积累下来的技术债误认成团队规范。一个更小、更新、更具代表性的示例，可能比整份搜索结果更有指导价值。决定哪个示例值得信任，本身就需要工程判断。

她怎样减少准备工作的负担

她当时做了一个 Claude Code 插件，让独立的子任务去找相关文档、历史改动和团队讨论，再通过提问把关键的缺口补上。留给主任务的是挑选后的材料。这样的准备也有成本，所以文章特意给快速原型留了位置：有时人自己也要先做出点东西，才知道想问什么。

编者手记

挑一个曾经返工的改动，找出当时最晚才说清楚的那句话。把它和支持它的一个文件、一个测试放在任务开头，再观察 Agent 在哪一步改变了决定。
