让 Agent 先把问题讲给你听

The Complete Guide to pstack Pt. 2

从哪里读起

一条 Slack 反馈通常混着现象、猜测和解决建议。Lauren 会把原始讨论交给 Agent，请它先复述问题。她由此能在任何改动发生前看见误解，也给 Agent 留出了挑战自己最初判断的空间。

再看一个细节

她以内部桌面框架 Dune 为例，先写一篇教人怎样用它构建应用的教程。写不清楚的步骤会暴露接口里的含糊。沿着教程倒推设计，双方手上都有一个可以实际走通的使用场景。

怎样知道一个设计值得选

在下拉菜单的例子里，几个方案可以放进同一个切换器，让人真的操作、对照截图和时序。服务边界的例子则比较调用方要写的代码、类型和接口。两个例子用了不同证据，回答的都是同一件事：哪一种差异会让使用者的处境变好？

编者手记

试着把缺陷报告里的解决方案遮住，只保留用户观察到的事实。让两个同事各自复述一遍，看看他们描述的是否真是同一个问题。
