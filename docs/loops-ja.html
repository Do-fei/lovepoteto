朝食の卵から考える、開発のボトルネック

Loops You Can Trust

読む手がかり

卵とトーストとコーヒーを一緒に出したい。トースターがどんなに速くても、卵がゆで上がるまでの三分は縮まらない。アンディ・グローブの朝食のたとえを借りて、ローレンは問いかける。エージェントとソフトウェアを作るとき、後の作業すべてを待たせているのはどの工程だろう。

具体例を読み解く

Cursor の性能調査は、その答えの一例だ。エージェントが開発版を起動し、利用者の操作を再現してプロファイルを記録し、変更後に同じ測定をもう一度行う。人間のエンジニアが問題を捉えるときと同じ計測手段を渡すことで、その場限りだった調査が繰り返せる手順になる。

画面が同じに見えても見落としたこと

共有 UI ライブラリを StyleX に移行したとき、サンプルの画面は以前と同じに見えた。それでも社内で使うと、要素の重なり順や、別の場所からのグローバルスタイルへの依存が問題になった。次の移行では末端のコンポーネントを一つずつ扱い、クラスを消す前に利用箇所を調べた。問題の影響が小さくなり、どの判断が原因だったかもたどりやすくなった。

編集ノート

再測定で元の条件を再現できなければ、結果は「判断材料が足りない」と記録する。そこで立ち止まれる手順なら、次の仕事も任せやすい。
